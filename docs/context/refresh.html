OpenTaxRate · Design notes

Refresh, loading and tables

The refresh job downloads each publisher's newest files and replaces a state's rows. It is the only writer; the API only reads. Run with opentaxrate refresh [STATE...] [--dir D] [--force], which calls refreshAddressRates({ states, dir, force }).

Sources: src/ingest/refresh.ts, src/ingest/load.ts, src/ingest/downloads.ts, src/ingest/tiger.ts, src/db/schema.ts (and migrations/)

Order (refreshAddressRates in refresh.ts)

Step What Skipped when
1 Each SST state: latestSstFiles(dir), then loadSstState both file names already in sales_tax_data_releases (unless --force); or one of the two files is missing (logged)
2 Missouri: missouriFiles(dir), then loadSstState never; reloaded every run when wanted
3 Each of GEO_STATES: geo.fetch(dir), then loadGeoState never; their sources don't version alike
4 TIGER outlines for every range and map state: latestTigerFiles, then loadTigerShapes every target state already has rows from that file name (unless --force)

An empty state list means every state. --dir points at a folder of already-downloaded files, read before the web.

Downloads (downloads.ts)

  • latestSstFiles(dir?): lists streamlinedsalestax.org/ratesandboundry/Rates/ and /Boundary/ (or dir, recursively), parses names like OHB2026Q4SEP17.zip with FILE_NAME, keeps the newest per state and kind by year, quarter, month and day.
  • sstFileLines(file): async lines from a URL or path, unzipping .zip while streaming (fflate Unzip), so a 400 MB boundary file is never held whole.
  • archive.ts keeps every input under artifacts/sources/ (sourcesRoot), filed by URL (sourcePath): <host>/<path>/<file>, a query or POST in <path>/<16-hex id>/ with url.txt. Changed contents move the old copy to previous/<date>-<id>-<name>; sources/manifest.jsonl has a line per fetch. Downloads (downloadedChunks), live answers (archiveResponse, gzipped: fetchLayer pages, Louisiana's lookup pages keyed by parish and period, the TTR service's POSTs keyed by body, New Mexico's service metadata, the Streamlined and TIGER listings) and files read from --dir (keepLocalCopy, under the URL they come from) all land there; hand-written tables' publications are fetched only to be kept. A saved file is read back first (savedDownload): always for a name matching EDITION, otherwise while younger than OPENTAXRATE_DOWNLOAD_MAX_AGE_HOURS (24; 0 never); a saved .zip not starting with PK is deleted and fetched again. scripts/backup-sources.sh snapshots the folder with restic to R2.
  • latestTigerFiles(stateFips, dir?): tl_<year>_us_county plus tl_<year>_<fips>_place and _cousub per state, from www2.census.gov/geo/tiger/TIGER<year>/. The year is the newest local county zip, else the newest year whose county file answers a HEAD.

Loading (load.ts)

loadSstState(files: StateFiles)

One client.begin transaction per state:

  1. DELETE the state's rows from sales_tax_street_ranges, sales_tax_zip_ranges, sales_tax_jurisdiction_rates, sales_tax_jurisdictions, sales_tax_areas.
  2. COPY sales_tax_jurisdiction_rates from parseRateLine, then insert files.jurisdictions?.() (Missouri's workbook ids; the Streamlined files give none) in batches of 500.
  3. Stream boundaries through files.parseBoundary ?? parseBoundaryLine. Each distinct county|place|districts|JSON of ids gets an area id Number(fips) * 1_000_000 + counter. Street rows COPY into sales_tax_street_ranges in ~1 MB batches; ZIP rows wait in memory (one connection runs one COPY at a time).
  4. COPY ZIP ranges, then areas.
  5. Upsert both files into sales_tax_data_releases on (state, kind).

COPY runs through pipeline, so a failure mid-file ends the COPY and rolls the whole state back. copyLine escapes backslash, tab, newline and carriage return and writes null as \N.

loadGeoState(state, data)

One Drizzle transaction: merge shapes sharing kind:fips; delete and re-insert the state's rates and its data.jurisdictions (batches of 500); write its outlines as a new edition of the state's non-TIGER shapes (file not like tl_%) from data.boundariesFrom, else the day they're loaded (writeEdition, below); replace its sales_tax_data_releases rows, the rates row with data.ratesFirstListed as first_listed. Census outlines are kept.

loadTigerShapes(file, states)

One transaction per TIGER file: write a new edition of that kind's TIGER rows (file like tl_%) for the states in it, in force from January 1 of the file's year (a TIGER year's outlines are the legal boundaries on that day). Every county loads; a place or county subdivision loads only if namedPlaces finds it in a rate code or an area's place, which leaves out most Census places. So TIGER must load after rates and ranges, as step 4 does.

TIGER (tiger.ts)

readTigerZip(zip, kind, stateFips) reads the .shp and .dbf in a TIGER zip into Shape { kind, stateFips, fips, name, rings, bbox }, merging a town split across counties into one shape. STATE_FIPS maps every state and DC to its FIPS. contains(shape, p) tests a point against in-memory rings (odd ring count), used before shapes are in PostGIS (adapters such as Texas).

Outline editions (writeEdition)

A loader's outlines are history, not a replacement: writeEdition(tx, scope, shapes, from) compares the new edition with the open rows (ends_on = 9999-12-31) that scope selects. An outline whose geometry is identical (st_orderingequals) keeps its row, renamed and refiled. An open row the edition changes or drops ends the day before from, or is deleted when it starts on or after from, so loading the same edition twice leaves the same rows. A changed or new outline starts on from. The first edition of a scope starts at 0001-01-01: with no older edition held, it stands for every earlier date. Lookups read the row in force on their date (map-engine.html); the locator's typed-city checks read the newest. Verified supplemental outlines (verify-polygons.ts) carry their own source periods and aren't written this way. A geo source that dates its own outlines (GeoStateData.shapes[].startsOn/endsOn, Colorado's and Alaska's rate service) gives its whole history, which replaces the state's non-TIGER rows on load.

Supplemental tax areas keep their history the same way: indexVerifiedPolygons indexes the newest snapshot of each source and quarter (windowOf), each for its own window. Minnesota's quarterly layers (locgnrl_sales_usetax_areas_<YYYYQn>, listed by minnesotaSources, each service's own layer id) and Washington's LOCCODE_PUBLIC ZIPs (washingtonSources) are acquired for every quarter from HISTORY_FROM, oldest first; a quarter with no edition has no supplemental outline, and the lookup falls back to its dated ranges and Census outlines. Only a source's newest edition failing fails the run.

An edition's from is when its lines are in force, not when they were fetched: a TIGER year's January 1, a Texas quarter's first day; a source that doesn't say gets the day it's loaded, so a change between two loads is dated at the later one.

Invariants

  • A lookup never sees half a state: each SST state and each map state is replaced inside one transaction.
  • Open-ended rows end on 9999-12-31; queries test starts_on <= date <= ends_on.
  • OPENTAXRATE_HISTORY_FROM (default 2020-01-01) drops SST and Missouri rows that ended before it at parse time (sst-files.ts). It does not filter map states' rows.
  • Changing how street keys are built (address.ts) requires refresh --force for range states.
  • Schema changes go through pnpm db:generate into migrations/, applied by opentaxrate migrate.
