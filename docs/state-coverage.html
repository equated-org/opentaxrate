Four lookup methods

The state selects the lookup method. Address ranges assign house numbers directly to tax areas. Geographic lookup places an address on a map, then finds the jurisdictions around it. Both read dated rates and apply state-specific rules.

Geocoding uses Census and OpenStreetMap Nominatim, plus Mapbox when configured. The code compares their results and keeps an uncertainty margin. PostGIS then searches downloaded polygons. These are separate steps: geocoders find coordinates; PostGIS finds jurisdictions; the tax engine calculates the rate.

Address ranges: 25 states

Streamlined Sales Tax (SST) provides a common file format for 24 states. Each boundary row assigns a street’s house-number range, ZIP+4 range, or ZIP to a combination of taxing jurisdictions. A separate rate file gives those jurisdictions’ dated rates.

A house number must fall inside the published range and match its odd/even side, rather than equal a listed endpoint. The engine also checks street spelling, direction, ZIP/city, units, and dates. SST rows stay as database ranges; they are never converted to polygons.

The engine tries street ranges, ZIP+4, and an unambiguous ZIP. If those cannot settle the rate, it may geocode the address and use separately downloaded Census outlines to narrow the ZIP’s candidate areas. A street match without ZIP+4 can also be cross-checked on the map when the ZIP contains different rates. Conflicting evidence can produce a refusal.

Refresh, history, and code

SST refresh discovers each state’s newest rate and boundary files and skips already loaded releases unless --force is used. Boundary data streams into Postgres; repeated jurisdiction combinations share one area record. History is filtered by OPENTAXRATE_HISTORY_FROM, defaulting to 2020-01-01, and depends on what the files contain.

Missouri loads up to eight quarterly rate workbooks and its newest available boundary file. Its available history depends on those workbooks. Small special districts can remain ambiguous in map fallback.

Geographic lookup: 16 states

These states geocode first. PostGIS finds containing county, city, and district outlines; the engine combines their dated rates using each state’s rules. Close to a boundary, the engine checks whether crossing it could change the rate.

Some adapters download rate files, some collect data from services during refresh, and others load tables maintained in code. A service used during refresh is separate from a live tax lookup.

California: live authority lookup

California sends the street, city, and required ZIP to CDTFA’s live API. The response supplies the combined rate and tax-area code; our engine separates the configured state component from the local remainder.

The API supplies today’s rate. A request for a different date still returns today’s rate, with that limitation stated in the source string. No California rate dataset is loaded by refresh.

Limits and maintenance

  • Coverage means an implemented method. It does not guarantee that every address or special district can be resolved. Alaska’s source covers Commission members; geographic discovery can miss small districts.
  • Rates and borders have different histories. Dated rate records do not recreate past annexations. Geographic adapters commonly use current outlines.
  • Refresh needs an operator. Run or schedule the refresh command. Tables maintained in code and manually interpreted county rules need separate review.
  • Ambiguity is explicit. Conflicting ranges, missing outlines, or uncertain placement can return 422. Required state data that has not been loaded returns 502.
  • The scope is the general rate. Product taxability, exemptions, transaction sourcing, single-item caps, and comprehensive tribal treatment remain outside the engine.
Commands and coverage checks

pnpm refresh TX WA loads selected states; pnpm refresh selects all adapters. Apply migrations first. GET /v1/coverage lists methods and loaded releases, but does not verify complete district coverage or static-table freshness.

pnpm check --cases path/to/cases.csv compares expected rates through the normal lookup. Passing sampled cases establishes accuracy for those cases, rather than every address nationwide.

Terms

Address range

A span of house numbers assigned to a tax area. Matching can also depend on street side, unit, and dates.

146 Main St → even range 100–198 → tax area

Geocoding

Converting an address into a coordinate, with an accuracy estimate.

Address → longitude, latitude, uncertainty

Polygon and PostGIS

A polygon is a coordinate outline. PostGIS is the database extension that checks which outlines contain a point.

Coordinate → containing county / city / districts

Tax area

A combination of taxing jurisdictions shared by many addresses. Its applicable rate depends on the requested date.

State + county + city + districts → dated rate
