Typos and street lists: reading addresses the way people type them

A geocoder that corrects "Wilolw Branch Lane" to the real Willow Branch used to be thrown away, because our matcher demanded the exact street. Now it takes a street one letter off the typed one only when the typed ZIP's own street list has the found street and not the typed one. That tells a typo from a real street next door, which no model we tried could do.

Traced from src/geocoding/providers/match.ts, src/geocoding/locator.ts, src/geocoding/zip-streets.ts, src/ingest/street-names.ts, src/address.ts and scripts/audit-address.ts on main at 47495ba. Numbers measured on 2026-10-22 against the local database and live geocoders.

Why

Every geocoder answer passes through one gate, matchesAddress(), before its point is used. The gate compares the address the geocoder says it found with the one the customer typed, part by part: house number, street name, type, directions, and city or ZIP. It was strict on purpose. A geocoder that returns a nearby house on a different street would otherwise put the address on the wrong side of a city line, and the rate would be wrong.

Strict also meant that a one-letter typo cost the whole lookup. Typed "22419 Wilolw Branch Lane, Tomball, TX 77375", every geocoder that found the house answered with the correct spelling, Willow Branch, so every answer failed the gate, nothing placed the address, and the API refused it with a 422. Spelling alone can't fix this. "Byers Ln" and "Myers Ln" are one letter apart and are both real streets in Arkansas ZIP 72063, so a rule that accepts any one-letter difference accepted 460 of 600 real twins and near-misses in our test.

  • The decision. Accept a geocoder's street one letter from the typed one only when the typed ZIP's street list has the found street and doesn't have the typed one. The list is the evidence of which streets exist there.
  • Why not an LLM. Six small models on OpenRouter each mistook 12 to 138 of 300 real twins for typos, even when told about twins (below). The list costs nothing per call and was wrong on none of them.
  • Why not Jev. TypeSafe's Jev decided one answer in every bench run (Iowa State Highway 92), and the current code answers that address without it.
  • Out of scope. The public tier's geocoders (Photon and Pelias) rarely find a misspelled house at all, so a lookup without a key gets no answer to check. Typos of two letters or more stay refused.

The model

Figure 1 shows the objects a lookup touches. The street list is new: for each lookup, the locator loads the street keys in the typed ZIP once, from two tables, and hands them to every geocoder call with the address. A street key is the street's name as matching compares it, so "Forest" and "FRST" are one key (see the appendix).

Primary key (state, zip5, street_key). 2,313,037 rows for 17 states, 289 MB. Listed in scripts/snapshot.sh as a tax-data table, so snapshots carry it.

Rules

  • Exact first. A geocoder's street that matches the typed one, allowing abbreviations, a type left off, or a type word dropped from anywhere ("Forest Extension" for Forest Avenue Extension), is taken as before. An Extension is never dropped: Forest Ave Extension isn't Forest Ave.
  • A typo needs the list. A one-letter difference is taken only if the found street's key is in the typed ZIP's list and neither the typed key nor any of its alternate readings is.
  • Everything else must agree. Same house number, same ZIP (a matching city isn't enough here), same directions, same type or a typed line with no type.
  • One letter. One letter added, dropped or changed, or two neighbours swapped, measured on the name's own words ("Forset" against "Forest", not their keys).
  • Five letters. The real street's name must have five letters or more, so short pairs like Elm and Elk never ride on an incomplete list.
  • No list, no rule. Without a list for the ZIP (no ZIP typed, or a database error) the gate stays exact.

A lookup on a twin street

A caller types "186 Byers Ln" in Arkansas ZIP 72063, where Byers Ln and Myers Ln both exist, and a geocoder answers "186 Myers Ln".

The names are one letter apart, but the typed key BYERS is in the ZIP's list, so the typed street is real and the answer is for a different street. The gate rejects it, exactly as before, and the lookup goes on with the other geocoders' answers. This is the case every LLM got wrong in up to 46% of tries.

Refresh loads the lists

An operator runs refresh. Its new step 4 loads, for each of the 17 map-read states, the Census Bureau's TIGER address features for every county, reading only each file's attribute table (FULLNAME, ZIPL, ZIPR).

  1. List the files. latestTigerAddressFiles() reads the ADDRFEAT folder for the newest TIGER year: 254 county files for Texas.
  2. Skip what's loaded. A state whose rows came from the same TIGER year is skipped unless --force.
  3. Read six at a time. Each street name becomes a key for each ZIP beside it. Texas: 463,101 street-ZIP pairs in 33 seconds.
  4. Replace the state's rows in one transaction.

In 2026 the Census site answers one file each in VA, AL, LA, AK and MS with a 247-byte "Request Rejected" page and status 200, every time, from every client. The loader now counts only a zip, retries once, and then takes that county's 2025 file, whose streets are near enough the same. Before that fix those five states failed with "invalid zip data".

Deploy

Production runs the stack from /opt/opentaxrate on the opentaxrate host. The code was deployed the way the other deploys that day were: a backup tarball of the tree, git archive of main copied over it with deploy/.env kept, then build migrate api, run migrate, up -d api. Rather than download 1,300 county files again on the server, the 2.31 million rows were copied from the local load with pg_dump -t zip_street_names --data-only into pg_restore --single-transaction, which took 15 seconds.

The address-reading audit

The typo rule came out of a broader question: how do we know the parser and the gate handle addresses the way people type them? The answer was a new script, scripts/audit-address.ts. It reads real addresses from the National Address Database (NAD), which files every address already split into its parts, and checks two things with no network calls.

  1. Parts. The house number, directions and street type parseStreet() reads must be NAD's.
  2. Typings. The same address typed the ways people type it must still be the same street and still pass the gate against the address as filed: type abbreviated, spelled out or left off, directions spelled out, a unit before or after, lower case, periods, city and ZIP on the line, numbers spelled out, Saint and Mount and Fort, every highway and county road form, and a one-letter typo.

On 9,200 addresses from 46 states (57,262 typings) it found 1,435 failures in 10 kinds; after the fixes, 49 rare ones remain. A second, fresh sample of 10,120 addresses with the added typings then found the highway, unit and fraction cases in the table below.

Why not an LLM

We tested the alternative directly. Each model got the same question with a structured yes or no answer ("Is the found address the same postal address as the typed one?"), including a warning that two real streets can differ by one letter. The 900 cases were built from real streets in our range files: 300 typos of real streets that no street in their ZIP is spelled as, 300 pairs of real twin names in one ZIP (both names found in at least three ZIPs), 50 lettered roads, 150 same-name streets with another type, 100 with another direction, plus 10 rare forms from the audit.

  • Every model takes real twins for typos. Any one of them alone would turn some refusals into wrong rates.
  • Behind the list, a model only loses typos. With the list checked first, each model wrongly accepted nothing more, but caught fewer typos than the list alone.
  • Gemini wasn't tested. The OpenRouter account's zero-data-retention guardrail excludes its endpoint, a sensible setting for customer addresses that was left as is.
  • The whole test cost about $1.10, mostly GPT-5 nano and DeepSeek, which reason at length before answering.

Open questions

  • Should the public tier catch typos? Recommended: no change for now. Photon and Pelias find too few misspelled houses for the rule to see an answer; a keyed lookup is where it works.
  • Should the range states' list come from the new table too? Recommended: yes, later. Reading distinct keys from the range table takes about 16 ms for a large Ohio ZIP against 0.3 ms from the new table.
  • Should the audit run in CI? Recommended: yes, with a committed fixture of a few hundred NAD addresses and a failure budget, so a parser change that breaks a typing fails the build.
  • What about the production reload started before this deploy? Its image predates the Census refusal fallback, so its street-name step fails at Virginia and stops before the outline step. Recommended: once it ends, run refresh again without --force; street names are skipped as already loaded and the outlines step runs.
  • Is Jev still needed? Recommended: remove it. It decided one answer in every bench run, and that address is answered without it now.

Appendix: words and concepts this page assumes

Street key

The street's name as matching compares it: upper case, standard abbreviations, words run together. Two spellings of one street share a key.

parseStreet("88 Forest Lane").streetKey  → "FRST"
parseStreet("10522 Ridge Park Drive")    → key "RIDGEPARK", type "DR"

TIGER address features

The Census Bureau's per-county files of named street segments, each with the ZIP on its left and right side. Only the attribute table is read.

tl_2026_48201_addrfeat.zip  (Harris County, TX; 14.8 MB)
FULLNAME="Willow Branch Dr"  ZIPL="77375"  ZIPR="77375"

One letter apart

One letter added, dropped or changed, or two neighbours swapped (a Damerau edit distance of one), measured on the name's words without house, unit, directions or type.

WILOLW  vs WILLOW   → "OL" and "LO" swapped → one letter apart
CHESTNOT vs CHESTNUT → one change    → one letter apart
MAON vs MAIN          → one change, but MAIN has 4 letters → not taken

National Address Database

The US Department of Transportation's public address points, contributed by states and counties, with each address split into its parts. The audit sampled it by OBJECTID ranges per state.

AddNo_Full="5261"  St_Name="LITTLE TREE"  St_PosTyp="Street"
St_PreDir=""  St_PosDir=""  Zip_Code="…"

Map-read and range states

Range states (24 Streamlined members and Missouri) publish files listing streets and house ranges by rate area. Map-read states publish rate tables and outlines, so an address is placed on a map; they had no street list until this change.

range: AR GA IA IN KS KY MI MN MO NC ND NE NJ NV OH OK RI SD TN UT VT WA WI WV WY
map:   AK AL AZ CO FL HI ID IL LA MS MT NM NY PA SC TX VA

Twin streets

Two real streets in one ZIP whose names differ by one letter. The test kept only pairs whose names each appear in at least three ZIPs, so a single file's misspelling doesn't count as a twin.

HAYNES LN / WAYNES LN   BYERS LN / MYERS LN
BELTON ST / BENTON ST   KENTWOOD DR / KENWOOD DR
