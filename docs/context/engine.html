Engine dispatch, statewide states and California

addressRates in src/rates/index.ts is the engine's one entry point. It picks a method by state, calls that method, and shapes the result as an AddressRate. The range and map engines have their own notes (range-engine.html, map-engine.html).

Sources: src/rates/index.ts, src/rates/statewide.ts, src/rates/california.ts, src/rates/canada.ts

Dispatch

rateAt first answers a Canadian province or territory (isProvince, src/rates/canada.ts) like a statewide state: no province has local sales taxes, so provinceParts(code, date, zip) gives the GST or HST and the province's own PST, QST or RST as state parts, named ("GST", "British Columbia PST", "Ontario HST"), with stateRate their sum and locationCode the province code. It refuses (422) a date before 2013-04-01 and a postal code whose first letter isn't the province's; the address is never placed. reportingFor reads PROVINCE_REPORTING for it (the CRA's GST34, a note where a PST or RST is filed separately; Revenu Québec's FPZ-500 in Quebec). A US state given a Canadian postal code is refused. Then addressRates.at(query, date) checks in this order:

Order Test Method Calls
1 statewideRate(state, date, city) returns non-null statewide nothing else
2 state === "CA" authority california(query, date)
3 geoStateOf(state) map geoRateAt(state, await query.locate(), date, street, query.trace)
4 RANGE_FIPS[state] ranges sstRateAt({ ...query, state }, date)
5 none RateError(..., 422, undefined, "UNSUPPORTED_STATE")

addressRates.method(state) returns the same names for /v1/coverage, or null. addressRates.covers(state) checks ADDRESS_RATE_STATES, which is STATEWIDE_STATES + Object.keys(RANGE_FIPS) + GEO_STATES + "CA" + the 13 provinces and territories, sorted. A province's method is statewide; its codes never collide with a state's, and "CA" is California.

Note the map method always calls query.locate() up front; the range method passes locate down and calls it only when needed.

AddressRateQuery.trace is an optional Trace (types.ts) the map and range engines push into (see api.html for its fields). Statewide and California answers leave it empty. It never changes the AddressRate returned.

AddressRate

Field Meaning
state upper-cased two-letter code
rate combined decimal rate (0.0725 is 7.25%)
stateRate the kind: "state" part's rate
localRate rate - stateRate, rounded to 6 decimals
byType RatesByType: general, generalInterstate, foodDrug, foodDrugInterstate (types.ts). Filled from the Streamlined files by sstRateAt; every other method gives generalOnly(rate), the others null. A food rate is the rate where the state taxes food at that rate, not whether it does
parts RatePart[]: { kind: "state" | "county" | "city" | "district", name, code, rate, byType?, ids } (types.ts). describeParts (names.ts) fills name and ids after the engine answers, from the sales_tax_jurisdictions row keyed by the part's code split at its first colon (kx:2227016>3227999 → type kx, code 2227016>3227999): the row's name and ids. With no row, ids is {} and the name is the engine's (the map engine's shape name), else the state's name, else the loaded outline (sales_tax_shapes) whose fips is the code's last piece (county → county, city → place/cousub, district → district/place/cousub); null when none (most Streamlined districts)
match statewide, street, zip4, zip5, map, zip_area or authority
locationCode statewide: the state code; ranges: fips-county-place[-districts] or null when several areas share the rate; map: state code then each part's code; CA: the CDTFA tax area code
locationIds the range engine's matched area's sales_tax_areas.ids ({"Composite SER Code": "01726"}, Missouri's {"Jurisdiction Code": …}) when every matched area has the same ids, {} otherwise, and for WA washingtonLocationIds adds DOR's four-digit "Location Code": "1726" (the SER code without its padding zero, as the DOR lookup and the Combined Excise Tax Return give it); CA: californiaLocationIds(tac), {"Tax Area Code": "19034D900000", "Local Tax Area Code": "19034"}, the second the tax area code's first five digits (county and city, 998 unincorporated, as CDTFA-531-FL1 lists them), {} for a code that doesn't start with five digits; {} for every other engine. LocationIdsSchema (src/api-schema.ts) names these keys in the OpenAPI spec; any other key still passes
jurisdictions settled, or uncertain where the address could be in another combination of jurisdictions with the same total (the map engine's other side of a line within the margin; the range engine's other matched areas), or a state's lookup gave one local part for every local tax. The rate is settled either way.
alternatives the other combinations, each { locationCode, parts } with named parts and the same total; empty when settled
source a sentence naming the files and match, e.g. Streamlined Sales Tax files OHR... + OHB..., street match on 2026-10-21 (Missouri DOR files ... for MO)
reporting Reporting | null from reportingFor (reporting.ts): see below

addressRates.at calls rateAt (the engines), then describeParts(state, parts), then reportingFor(state).

Reporting (src/rates/reporting.ts)

A directory. STATE_REPORTING holds every state and DC; reportingFor(state) returns { agency: { name, url }, form, notes, locationKey }, or null for a state with no entry. form is null where there's no general sales tax return; notes is filing outside it (self-collected cities, remote seller programs). The codes a return files the tax under are the parts' ids and locationIds, passed through from each state's data; nothing here maps, renames or verifies them, and a Census FIPS code is never given as one. locationKey names the locationIds key the return files a location under (WA Location Code, CA Local Tax Area Code, MO Jurisdiction Code; null elsewhere), so a caller reads locationIds[locationKey] without knowing the state; test/reporting.test.ts checks each is a key LocationIdsSchema lists.

The source match phrases come from MATCH_NAMES.

Statewide (src/rates/statewide.ts)

RATES holds a newest-first list of { rate, from } per state: DE, NH, OR, MT at 0; CT 6.35%; ME 5.5%; MD 6%; MA 6.25%; DC 6%. STATEWIDE_STATES = Object.keys(RATES).

statewideRate(state, date, city) returns:

  • null for a state not in RATES;
  • { refused } for Montana when the upper-cased city (dots removed) is in MONTANA_RESORT_AREAS;
  • { refused } when date is before the oldest from;
  • else the first entry with from <= date.

Invariants: rates are dated and a sale before the first date is refused, not given today's rate. Rates on particular goods (meals, IT services) are not the general rate and are not here. Streamlined members with one rate (IN, KY, MI, NJ, RI) come from their own files, not this table. Alaska is a map state, not statewide.

California (src/rates/california.ts, california() in index.ts)

California publishes no address files. It answers first from CDTFA's dated tax-area polygons, verified at ingestion, and otherwise reads CDTFA's live GetRateByAddress service, which gives today's rate only.

Indexed tax areas (ingest/verify-polygons.ts): each verified CDTFA tax area is an ordinary sales_tax_areas row built by verification (id from 06 × 1,000,000 + 900,001, no county or place, one district tac:<code>), with an area:<id>:<from> outline linked by area_id and a dated tac row in sales_tax_jurisdiction_rates holding CDTFA's total. A feature that can't be verified is a held: marker. The area isn't rated by rateAreas: that stacks a 45:<fips> state row and each part's own row, but CDTFA publishes only the total, and California isn't in RANGE_FIPS. Adding a state row would invent a split CDTFA doesn't publish and make California a range state, so the lookup reads the area's tac row instead.

california(query, date) in index.ts:

  • only when californiaIndexedOn(date) (an area outline or held marker is live on the date) is the address placed, and californiaIndexedRate asked. It reads outlines through indexedTaxAreas("CA", [], …) like every verified area, with no ZIP candidates (all of California's are built areas), then the areas' tac rows on the date. One area with one dated rate answers: match map, locationCode the TAC, parts CA and tac:<code>, source "CDTFA indexed tax area …". Near an edge it asks once for a sharper point. Held, conflicting, undated or still near an edge, it falls through to CDTFA below;
  • with a ZIP, calls californiaSalesTaxService.lookup({ street, city, zip }); when CDTFA's match isn't confident (422), asks at the map point instead (atMapPoint);
  • without a ZIP (CDTFA requires one), asks at the map point first: atPoint at the geocoded point and at the edges of its margin past CDTFA's 50 m buffer (marginProbes), answering only when every probe gives the same single tax area. If that doesn't settle it, the standardizer's ZIP goes to lookup; with neither, 422;
  • splits the answer into a state part at CA_STATE_RATE (0.0725) and one district part tac:<code> for the rest;
  • says in source when the date asked is not today ("today's rate, not dated to ...").

californiaSalesTaxService.lookup rules:

Case Result
HTTP 400 422, address rejected
other non-OK 502
timeout (10 s) 504
network error or bad JSON 502
response fails the zod schema 502
not exactly one taxRateInfo, or geocode not confidence: "High", calcMethod: "Rooftop", and one match code "Good" 422 with a reason
otherwise { rate, locationCode: tac, lookedUpAt, ... }

Only five digits of the ZIP are sent.
