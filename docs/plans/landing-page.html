Design plan · proposed · branch frantic-yak · 2026-10-21

Landing page: search an address, see its rate and where it fell

A one-page site under landing/: a search box with address autocomplete, the rate broken into its parts, and a map that draws the exact points, outlines and margin the engine used to decide. It's a static build with no sign-in and no server of its own, so Vercel, Cloudflare Pages or any file host can serve it. The API it calls sits behind Cloudflare, which limits each IP before a request costs anything.

Traced from src/server.ts, src/lookup.ts, src/engine/index.ts, locate.ts, geo-lookup.ts, shapes.ts, and ~/code/openfinance-landing (SvelteKit 2, Svelte 5, Tailwind 4). Prices fetched 2026-10-21. The Austin coordinates, distances and jurisdiction codes in the running example are illustrative until phase 1 runs it against the loaded data.

Why a landing page, and why this shape

Today the only way to see OpenTaxRate work is to clone it, load data for 45 minutes and curl it. A page where someone types an address and sees 8.25%, split into state, city and transit district, with the street and the city line drawn on a map, shows what the README claims in about five seconds. It also shows what sets the project apart: it explains each answer and refuses when it can't be sure.

The decision is to build a static SvelteKit site, styled like openfinance-landing with pixel-art accents. The browser calls three services directly: an OpenStreetMap-based autocomplete (Geoapify to start), OpenFreeMap tiles drawn by MapLibre, and our API. The API gets one addition, an opt-in trace on the response that carries the geocoder points, the margin and the outlines, so the map draws what the engine used.

  • Static, not SvelteKit-on-a-server. With adapter-static the build is plain files. Vercel's Hobby plan, Cloudflare Pages and Netlify serve that for free, and there's no function to meter or rate limit on the landing host.
  • OpenStreetMap data end to end, not Mapbox. Mapbox's terms appear to require that Mapbox search results are drawn on a Mapbox map. Pairing Mapbox autocomplete with a free basemap would break that, and pairing it with Mapbox GL means paying for map loads too. OSM-based autocomplete and tiles can be drawn anywhere with attribution.
  • The trace comes from the engine, not from the browser. The map shows the Census and Nominatim points the API actually compared, the margin it actually used, and the outlines it actually tested, not a pin from the search box.
  • Rate limits live in front of the API. The landing page has nothing to protect. The API is what spends geocoder quota and database time, so it sits behind Cloudflare, with a per-IP limit inside it as well.

Out of scope: accounts, API keys for the public, a docs site (the README stays the docs for now), batch upload, and hosting the API itself, which the open questions cover.

Short answers to the questions

  • Autocomplete: Mapbox free tier? It works, but it's the expensive choice. Search Box gives 500 free sessions a month, then $3 per 1,000 at its introductory price, or $11.50 per 1,000 after 2,500 free at its listed standard price. It also commits the map to Mapbox. Start with Geoapify's free plan (3,000 requests a day, hard-stopped, no card), and move to a self-hosted Photon when traffic passes about 15,000 lookups a month. Pelias is heavier than we need: it wants Elasticsearch and several importers, whereas Photon is one Java process over a prebuilt OSM index.
  • Can the map show exactly how the address was placed, without Mapbox? Yes. MapLibre GL JS (open source) draws OpenFreeMap's vector tiles, which are free with no key and no cap. On top go three layers from the API's trace: each geocoder's point, the margin circle, and the county, city and district outlines with the distance to the nearest edge. The pixel touches (a pin, dithered fills) are just MapLibre layer styles.
  • Rate limiting: per IP, or let Cloudflare do it? Both. Cloudflare doesn't rate limit on its own. It absorbs floods for free, but a per-IP limit needs a rule, and the free plan includes one. Put the API's hostname behind Cloudflare with one rule for bursts, and keep a per-IP minute and day count inside the API, keyed by CF-Connecting-IP.
  • Is it expensive? No, if we skip Mapbox. At 10,000 lookups a month the recommended stack costs about $15, and that's the server the API already needs. With Mapbox search and maps it's about $50, and at 100,000 lookups it's about $45 against $620 or more. The cost table has the arithmetic.

What it looks like

The page starts as nearly nothing: a small pixel wordmark, one sentence, and a wide rounded search box, like Google's or Claude's new-chat screen. Under the box sit three example addresses, one per engine (a Texas map lookup, an Ohio street-range lookup, an Oregon no-sales-tax address), so a visitor can see a result without typing. Once a lookup returns, the search box moves to the top, the rate shows on the left, and the map fills the right.

The pixel art stays small and in a few fixed places: the wordmark in a pixel face (Departure Mono, open-licensed), a pixel map pin, a pixel bar that splits the rate into its parts, a dithered fill for the city outline, and a pixel progress strip while the lookup runs. Everything else uses Inter on white, with the same tokens and dark mode as openfinance-landing.

Model: three places code runs

Figure 2 shows where each piece runs. The browser loads a static bundle from the landing host, then talks to three services directly: the autocomplete provider while the visitor types, the tile server while the map draws, and our API once per lookup. Only the API is ours to pay for and protect. It already exists. This plan adds CORS, a limiter, a short cache and the trace.

Rules

  • The landing page builds and deploys alone. landing/ has its own package.json and lockfile and imports nothing from src/. Vercel's root directory is landing. The API's Dockerfile and tsconfig ignore it.
  • The map draws only what the engine used. Every mark on the map comes from the response's trace. The autocomplete's coordinate is used only to center the map when there's no trace point, as in a street-range answer, and it's labeled that way.
  • Draw a provider's coordinates only where its terms allow. Census and Nominatim points can go on any map. The public demo API runs without MAPBOX_ACCESS_TOKEN, so it never returns a Mapbox point to draw on a non-Mapbox map.
  • A refusal is a result, not an error. A 422 shows its message and the candidate rates with the same care as a rate, and the map shows the line the address was too close to.
  • One lookup per pick. Typing calls only the autocomplete, with a 250 ms debounce and at least 4 characters. The API is called when a suggestion is picked or an example is clicked, never per keystroke.
  • trace is opt-in. Without include=trace, /v1/rate returns exactly what it returns today. Self-hosters see no change and no added queries.
  • Keys in the bundle are public and restricted. The Geoapify key is limited to the landing's origins in Geoapify's console. Its free plan stops at its daily cap, so a stolen key causes an outage, not a bill.

The engines take an optional trace object and push into it. Their return types don't change, so the CLI, the tests and every caller that omits trace behave as they do today. Coordinates are rounded to 5 decimals (about 1 m) and outlines to about 5 m, which keeps a typical response under 40 KB.

The progress strip fills, the search box slides to the top, and the result appears, typically within a second for a cached or range answer and about 2 seconds for a map answer that waits on the geocoders.

4. See where it fell

The map is the part the user asked to show exactly. It draws the engine's own geometry over a muted OpenFreeMap basemap: the outlines it tested (city with a dithered fill, district dashed, county dotted), each geocoder's point, the chosen point as a pixel pin, the margin as a dashed circle, and a thin line to the nearest edge with its distance. A small zoomed inset shows the points and the margin at street scale, where the agreement is visible.

The visitor sees the pin on the Capitol, the city's dithered fill around it, and "nearest city edge 2.1 km", which is why the answer is certain.

5. A refusal or a limit

Some lookups don't end in a rate. A 422 shows the API's message and its candidate rates, with the map drawing the line that was too close. A 429 says how long to wait, and a 502 or 504 says a data source is down.

   + Retry-After: 42

The visitor reads why there's no single answer, sees the line, and knows what to confirm.

Rate limiting

The direct answer: limit per IP, in two layers, both in front of the API, because the landing page has nothing to protect. Cloudflare doesn't rate limit automatically. Its DDoS protection is automatic and free, but a per-IP limit is a rule you write, and the free plan includes one. A Vercel firewall rule wouldn't help either, since it only guards what Vercel serves, and the API isn't there.

  1. Edge rule, at Cloudflare. The API's hostname (say api.opentaxrate.com) is a proxied DNS record. One rule blocks an IP for 10 seconds after 20 requests to /v1/rate in 10 seconds. That stops scripts before they reach the server, at no cost.
  2. Per-IP counts, in the API. src/limits.ts keeps a minute and a day counter per IP in memory: 10 lookups a minute and 200 a day, set by OPENTAXRATE_PUBLIC_LIMIT=10/min,200/day. It's off when unset, so self-hosters are unaffected. The key is CF-Connecting-IP, trusted only when OPENTAXRATE_TRUST_CF=1, and the origin's firewall accepts only Cloudflare's IP ranges, so the header can't be forged. One container means memory is enough, with no Redis.
  3. A 24-hour answer cache. A repeated address (every example chip, every shared link) is answered from memory without touching Nominatim. That also keeps us inside Nominatim's 1-request-a-second policy, which the engine already spaces to.
  4. Autocomplete limits itself. The Geoapify key is restricted to our origins, and the free plan's daily cap is a hard stop, not overage.

If bots get past this, add Cloudflare Turnstile, a free invisible challenge, on the first lookup of a session. That's left out of v1 because it adds a script and a token round-trip for every visitor.

Phases

There's no data model or migration. The trace reads tables that already exist. So the order is: the API change, then the page, then the map, then deploy.

Phase 1: the API explains itself (one PR)

Later: self-host Photon

When lookups pass about 15,000 a month, or Geoapify's free cap blocks visitors on busy days, run Photon with the US extract on its own VPS and set PUBLIC_SUGGEST=photon. suggest.ts already has the adapter.

Open questions

  • Where does the public API run? Recommended: one small VPS running the existing docker compose, restored from the release snapshot, with Cloudflare in front. Vercel can't run it, because it needs Postgres with PostGIS and a long-lived process.
  • Drop Mapbox from the demo API? Recommended: yes. Without the token, the map draws every point the engine used, and the cost is zero. The cost is that some map-engine addresses that only Mapbox could place come back as "couldn't be placed". Measure how many on the Texas check set before deciding. If it's more than 1 to 2%, keep Mapbox in the API and show "Mapbox agreed within N m" as text, without its dot.
  • Geoapify or Photon from day one? Recommended: Geoapify. Self-hosting Photon is a second server to run before anyone has visited. Its US address coverage is the same OSM data, so switching later changes nothing for visitors.
  • Vercel or Cloudflare Pages for the landing? Recommended: either works, since the build is static. Pick Vercel if the project is non-commercial or you'll pay for Pro anyway. Pick Pages if you want the API's DNS, rules and site in one dashboard, as openfinance-landing does.
  • Which domain? Recommended: opentaxrate.com for the page and api.opentaxrate.com for the API, so CORS allows exactly one origin plus preview URLs.

Appendix: words and concepts this page assumes

Autocomplete session

The run of suggestion requests one person makes while typing one address, billed as a unit by Mapbox (up to 50 suggests and 1 retrieve, ending after 2 minutes idle). Geoapify bills each request instead.

"1"  "11"  "110" (min 4 chars: no call)
"1100" → suggest   "1100 Cong" → suggest   pick → retrieve
Mapbox: 1 session    Geoapify: 2 requests

Margin

How far a line must be from the point before the engine trusts which side it's on. It's set by the geocoder's accuracy, or by the spread between geocoders when that's wider (EDGE_METRES in types.ts).

EDGE_METRES = { rooftop: 15, parcel: 25, point: 40, interpolated: 75 }
best = nominatim (point), spread 14 m < 40 m → margin 40 m
spread > 250 m → address not placed (MAX_SPREAD_METRES)

MapLibre GL JS

The open-source fork of Mapbox GL JS (BSD license). It draws vector tiles from any server with WebGL, with no key and no per-load fee.

new maplibregl.Map({ container, style: "https://tiles.openfreemap.org/styles/positron" })
map.addSource("outlines", { type: "geojson", data: trace.outlines })

OpenFreeMap

A free public host for OpenStreetMap vector tiles and styles, with no key, no registration and no request cap, funded by donations. Commercial use is allowed. It can be self-hosted if it ever goes away.

style: https://tiles.openfreemap.org/styles/positron
attribution: © OpenMapTiles © OpenStreetMap contributors

Photon

An open-source, search-as-you-type geocoder over OpenStreetMap, one Java process over a prebuilt index that GraphHopper publishes weekly, including per-country extracts. Pelias does the same with Elasticsearch and several importers, so it has more to run.

java -jar photon.jar -data-dir ./photon_data   # US extract
GET /api?q=1100+congress&layer=house&bbox=-125,24,-66,50

CF-Connecting-IP

The header Cloudflare adds with the visitor's real IP when it proxies a request. It's only trustworthy when the origin refuses connections that don't come from Cloudflare.

key = env.OPENTAXRATE_TRUST_CF ? req.header("cf-connecting-ip") : socket.remoteAddress
bucket[key].minute += 1  → 11 > 10 → 429, Retry-After = seconds left in minute

adapter-static

The SvelteKit adapter that prerenders every route to HTML, JS and CSS files at build time, so any static host can serve the site and no server code runs per request.

// svelte.config.js
import adapter from "@sveltejs/adapter-static";
export default { kit: { adapter: adapter() } };
// src/routes/+layout.ts
export const prerender = true;

CORS

The browser rule that a page on one origin may read responses from another only if that server allows it. The landing on opentaxrate.com needs the API on api.opentaxrate.com to say so.

GET /v1/rate  Origin: https://opentaxrate.com
← Access-Control-Allow-Origin: https://opentaxrate.com
